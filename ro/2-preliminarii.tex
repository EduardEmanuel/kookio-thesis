\chapter{Preliminarii}\label{ch:prelim}

\section*{Contextul tehnologic}
Proiectul \textit{Kookio} este fundamentat pe arhitectura unitară \textbf{PAN} (Prisma–Analog–Nx), concepută pentru a acoperi întregul flux de dezvoltare \texttt{TypeScript}, de la interfața utilizatorului până la stratul de persistență.
Această arhitectură consolidează într-un cadru comun mecanismele de orchestrare, randare hibridă și acces tipizat la date, oferind premisele unei aplicații coerente și extensibile \cite{nx,analog,prisma}.

Rolul acestui capitol este de a introduce conceptele și tehnologiile care stau la baza implementării, fără a intra încă în detalii de ordin practic.
Manifestul arhitectural complet, alături de avantajele comparative și direcțiile de evoluție, este prezentat în \textbf{Anexa~\ref{ch:appendix-manifest}}.

\section{Cadrul tehnologic}

\subsection{Arhitecturi web moderne}

Modelul tradițional client--server, în care browserul acționa exclusiv ca un consumator de API-uri REST, nu mai răspunde integral cerințelor aplicațiilor web actuale.
Așteptările privind performanța, experiența utilizatorului și vizibilitatea în motoarele de căutare au condus la apariția unor paradigme de randare mai flexibile, în care responsabilitățile sunt distribuite între client și server \cite{analog,nitro}.

În acest context, se disting mai multe strategii de randare:
\begin{itemize}
  \item \textbf{Client-Side Rendering (CSR)}, care maximizează interactivitatea în browser;
  \item \textbf{Server-Side Rendering (SSR)}, orientată spre livrarea rapidă a conținutului inițial;
  \item \textbf{Static Site Generation (SSG)}, potrivită pentru conținut stabil și public;
  \item \textbf{arhitecturi hibride}, care combină aceste tehnici în funcție de tipul rutei și de dinamica datelor.
\end{itemize}

Aplicația \textit{Kookio} adoptă o astfel de arhitectură full-stack hibridă, în care frontend-ul și backend-ul sunt dezvoltate împreună, într-un flux unitar.
Această decizie permite partajarea tipurilor și a mecanismelor de validare între straturi, reducând riscul erorilor de integrare și sporind coerența aplicației \cite{trpc}.

\subsection{Angular și randare server-side}

Angular este un framework matur, construit în jurul limbajului TypeScript și orientat către dezvoltarea de aplicații web scalabile și bine structurate \cite{angular_signals}.
Deși utilizat inițial preponderent în scenarii de tip client-side rendering, ecosistemul Angular a evoluat semnificativ în direcția suportului pentru randare server-side.

În cadrul proiectului \textit{Kookio}, acest suport este furnizat de \textbf{Analog}, un meta-framework care extinde Angular cu funcționalități full-stack, precum:
\begin{itemize}
  \item randare server-side (SSR),
  \item rutare bazată pe structură de fișiere,
  \item integrarea logicii de server în aceeași aplicație \cite{analog}.
\end{itemize}

Randarea pe server permite generarea HTML-ului inițial înainte ca aplicația să ajungă în browser, îmbunătățind atât timpul de afișare perceput, cât și compatibilitatea cu motoarele de căutare \cite{nitro}.
Pentru o aplicație orientată către conținut și uz casnic, precum Kookio, aceste aspecte devin relevante încă din primele interacțiuni ale utilizatorului.

\subsection{Monorepo și orchestrare cu Nx}

Gestionarea complexității unui proiect full-stack presupune o organizare clară a codului și a proceselor de build.
În acest scop, proiectul \textit{Kookio} este structurat ca monorepo, utilizând instrumentul \textbf{Nx} \cite{nx}.

Această abordare permite gruparea într-un singur repository a aplicației web și a bibliotecilor asociate, fiecare cu responsabilități bine delimitate:
\begin{itemize}
  \item interfața utilizator și logica server-side,
  \item accesul la date și modelele ORM,
  \item validarea contractelor de date,
  \item utilitare și date mock reutilizabile.
\end{itemize}

Nx adaugă peste această structură mecanisme de execuție incrementală, caching și izolare logică între proiecte.
Astfel, modificările locale pot fi propagate eficient, fără a afecta întregul sistem, un avantaj esențial în dezvoltarea iterativă a aplicațiilor full-stack.

\subsection{tRPC și partajarea tipurilor}

Un element central al arhitecturii PAN îl reprezintă comunicarea type-safe dintre client și server.
În acest scop, proiectul utilizează \textbf{tRPC}, un framework care elimină necesitatea definirii manuale a contractelor API \cite{trpc}.

Procedurile tRPC sunt declarate pe server și consumate direct în aplicația Angular, beneficiind de:
\begin{itemize}
  \item inferență completă a tipurilor TypeScript,
  \item validarea automată a datelor de intrare prin scheme Zod \cite{zod},
  \item sincronizarea implicită a contractelor între straturi.
\end{itemize}

Această abordare simplifică semnificativ integrarea și creează un cadru robust pentru extinderea ulterioară a funcționalităților.

\subsection{Persistență: Prisma și CockroachDB}

Stratul de persistență al aplicației este construit pe baza ORM-ului \textbf{Prisma} și a sistemului de gestiune a bazelor de date \textbf{CockroachDB} \cite{prisma,cockroachdb}.
CockroachDB oferă un model NewSQL distribuit, compatibil cu protocolul PostgreSQL, permițând atât consistență tranzacțională, cât și scalare orizontală \cite{postgresql}.

Prisma joacă rolul de interfață declarativă între aplicație și baza de date, fiind responsabilă pentru:
\begin{itemize}
  \item definirea schemei relaționale,
  \item generarea automată a clientului TypeScript,
  \item gestionarea migrațiilor între versiuni ale structurii de date.
\end{itemize}

Această combinație oferă un echilibru între stabilitatea ecosistemului SQL și flexibilitatea necesară evoluției aplicației.

\subsection{Testare automată: Vitest și Playwright}

Asigurarea calității aplicației presupune validarea comportamentului acesteia la mai multe niveluri.
În proiectul \textit{Kookio}, acest obiectiv este atins prin combinarea testării unitare cu testarea end-to-end.

Pentru testele unitare și de integrare este utilizat \textbf{Vitest}, ales pentru viteza de execuție și integrarea nativă cu ecosistemul Vite \cite{vitest,vite}.
Acesta permite testarea logicii de business și a componentelor într-un mediu controlat.

Testarea end-to-end este realizată cu \textbf{Playwright}, care simulează interacțiuni reale ale utilizatorului în browser \cite{playwright}.
Prin această abordare sunt validate fluxurile critice ale aplicației, de la încărcarea inițială a paginii până la comunicarea cu API-ul server-side.

\subsection{Managementul configurației și mediilor}

Configurarea aplicației este gestionată centralizat prin platforma de deployment \textbf{Vercel}, care acționează ca sursă unică de adevăr pentru variabilele de mediu \cite{vercel_cli}.
Această strategie permite separarea clară a mediilor de dezvoltare, testare și producție, reducând riscurile asociate gestionării locale a secretelor.

Pentru dezvoltarea locală, Vercel CLI este utilizat pentru sincronizarea temporară a variabilelor active, asigurând alinierea mediului local cu cel de deploy, fără introducerea fișierelor sensibile în repository.
